# 开发路线图

> 目标：3 个月（2026-08 至 2026-10）走通全链路，用于数据开发实习面试。
> 每完成一项勾掉；每完成一个阶段 git commit 一次，README 更新进度。

## Phase 0 · 环境搭建（第 1-2 周）

**任务**
- [ ] 3 台 CentOS 7.9 虚拟机（hadoop101/102/103，每台 4G）
- [ ] 静态 IP / 主机名 / 免密 SSH / JDK 1.8
- [ ] Zookeeper 3.5.7 + Hadoop 3.1.3 全分布式部署
- [ ] shell/tools 脚本可用（xsync / xcall / jpsall / zk.sh / cluster.sh）
- [ ] HDFS 副本数改 2，目录规范按 tech-stack.md 第 6 节
- [ ] 踩坑日志开记（见 [踩坑日志](踩坑日志.md)）

**验收标准**：三节点 `jpsall` 全绿；HDFS 上传/下载文件成功；NameNode WebUI（9870）与 Yarn WebUI（8088）可访问。

## Phase 1 · 数据采集（第 3-4 周）

**任务**
- [ ] mysql/business_ddl.sql：业务库建表（用户/商品/订单/支付/退款/优惠券）
- [ ] data-generator：业务数据生成器（写 MySQL）+ 行为日志生成器（写 JSON 日志）
- [ ] Flume + Kafka 链路：日志 → Kafka → HDFS（ODS）
- [ ] DataX：MySQL → HDFS（ODS，全量初始化 + 增量同步）
- [ ] 造出 3-6 个月历史数据（拉链表初始化必需）

**验收标准**：ODS 层表当日有数据；日志 JSON 正确落 HDFS 并按天分区；增量同步不丢不重。

## Phase 2 · 数仓建模（第 5-8 周，核心）

**任务**
- [ ] DIM：用户拉链表（重点）+ 商品/分类/地区/时间维度
- [ ] DWD：流量明细（启动/页面/事件）+ 交易明细（订单/支付/退款）
- [ ] DWS：用户/商品/地区/时间四主题宽表
- [ ] ADS：交易/流量/用户指标（口径见 architecture.md 第 5 节）
- [ ] 全部 SQL 进 spark-jobs/，`dt` 参数化

**验收标准**：按 [表清单](tables.md) 全部建出并跑通；指标数值能与手工抽样核对一致；每张表能讲清粒度与口径。

## Phase 3 · 调度 + 质量 + 可视化（第 9-10 周）

**任务**
- [ ] Airflow 部署 + 全链路 DAG（ODS→DIM/DWD→DWS→ADS→导出）
- [ ] quality 检查脚本（行数/主键重复/空值/指标环比）接入调度
- [ ] DataX 导出 ADS → MySQL
- [ ] Superset 可视化（GMV 趋势 / UV / 留存 / 转化漏斗，可选加分）
- [ ] README 补架构图 + 完整表清单 + 指标口径

**验收标准**：每天定时自动跑通全链路；质量检查通过；断点失败能重试恢复。

## Phase 4 · 面试准备（第 11-12 周）

**高频问题清单（每个都要能指着代码讲）**
1. 数仓为什么分层？每层职责是什么？
2. 拉链表原理？为什么不用每日全量快照？
3. 维度建模 vs 范式建模？星型模型为什么更适合数仓？
4. 数据倾斜怎么发现、怎么处理？
5. HDFS 小文件问题怎么产生的、怎么解决？
6. 增量/全量同步策略怎么选？
7. 写过 UDF/UDTF 吗？什么场景？
8. 调度失败怎么恢复？数据重复怎么兜底？
9. 指标口径怎么定的？（GMV/留存/复购）
10. 集群多大？内存怎么分配？（呼应本项目 3×4G）

**面试陈述主线**：数据从哪来 → 怎么采集 → 怎么建模 → 怎么计算 → 怎么调度 → 怎么保证质量，3 分钟讲完，之后按追问展开。

## Git 纪律

- 每完成一个子任务就 commit，message 带阶段前缀，如 `docs: 拉链表设计`、`dwd: 订单明细清洗 SQL`
- 面试时 commit 历史 = 持续交付能力的证明
